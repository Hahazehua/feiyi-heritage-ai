# 受控偏好推断策略

## 1. 目的

当用户已经给出明显赠礼对象或场景，但没有说明非关键审美偏好时，系统可以补充一个可修改的推荐方向，减少机械追问。推断只用于候选评分和方案表达，不得创造产品、商业或用户身份事实。

实现集中在：

- `src/heritagelink/inference_policy.py`
- `src/heritagelink/recommendation_context.py`

## 2. 允许字段

| 字段 | 示例 | 用途 |
|---|---|---|
| `style_preferences` | 典雅、庄重、喜庆 | 软偏好评分 |
| `symbolism_preferences` | 文化传承、感谢、祝福 | 软偏好评分与方案表达 |
| `packaging_requirement` | 与商务场景相符的稳妥包装方向 | 方案建议，不作为产品能力 |
| `output_language` | 海外礼赠优先中英双语 | 内容展示偏好 |

每项内部记录 `field_name`、`value`、`reason`、`confidence` 和 `source=local_scenario_policy`。用户明确提供的值拥有最高优先级，推断不会覆盖。

## 3. 当前规则

- 海外商务合作伙伴、商务礼赠或周年纪念：典雅/庄重、文化传承/纪念；
- 教授、教师或长辈：典雅/传统、文化传承/感谢；
- 婚礼或新人：喜庆/温暖、祝福/相伴；
- 明确海外客户或国际场景：文化辨识度方向和中英双语内容。

## 4. 禁止字段

禁止推断预算、总预算、单价、数量、定制是否必需、Logo、目的地、交期、运输能力，以及任何产品价格、库存、产能、材料、尺寸、认证、传承人、官方资质或商家定制能力。

`INFERABLE_FIELDS` 是写入白名单，`FORBIDDEN_INFERENCE_FIELDS` 提供额外审计断言。推荐仍先执行用户明确硬约束；推断值不能成为新的商业硬约束。

## 5. 客户表达

界面不显示“AI 推断字段”。它显示“我会先按……方向为您匹配”，并提供“调整需求”。分析数据在用户授权后分别记录 `user_provided_fields` 和 `inferred_fields`，避免把推断值误认成用户陈述。
