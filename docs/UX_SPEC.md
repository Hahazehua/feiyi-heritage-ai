# 飞颐礼遇单页面对话体验规格

## 1. 默认体验

用户打开应用后直接进入“选取您的定制专属礼品”。首屏包含品牌、顾问欢迎语、聊天记录、聊天输入、四个快捷需求，以及次级入口“我想直接填写需求”。产品不要求用户先理解技术模式或选择复杂功能页。

主路径固定为：

```text
用户描述需求 → 顾问自然追问 → 当前需求摘要 → 推荐产品
→ 结构化比较 → 对话调整或缩小范围 → 用户选择产品
→ 生成专属礼品方案 → 下载方案
```

所有阶段在同一页面逐步出现。`st.session_state` 保存当前会话、累计需求、推荐、选择和方案；聊天使用 `st.chat_message` 与 `st.chat_input`。

## 2. 对话规则

- 每轮最多主动提出一个问题；
- 优先询问能显著改变推荐的对象、场景、预算、数量、交付和必要定制条件；
- 已有明显方向、用户要求直接推荐、用户跳过、已达到 5 次主动追问或没有新的高价值问题时进入推荐；
- 用户始终可以点击“先为我推荐”；
- DeepSeek 失败时继续使用已有条件，不在主界面显示 API、认证、余额、JSON、解析器或堆栈信息。

## 3. 当前需求摘要

摘要只使用客户语言显示：赠礼对象、场景、预算、数量、风格、文化寓意、定制、Logo、交付和目的地。未知项不以内部字段或红色警告呈现；页面使用“可以随时调整”“可后续沟通”等表达。

如果应用了受控软偏好，页面显示自然方向，例如“我会先按庄重、适合商务纪念与文化交流的方向为您匹配”。用户通过“调整需求”可以覆盖该方向。

## 4. 推荐与最终方案

推荐最多 3 件。产品卡默认显示图片、名称、2–3 句内推荐理由、适用对象/场景、文化方向、目录价格和可用定制方向。八维评分解释只在“为什么推荐给我？”展开区出现。

当当前正式推荐有 2–3 件时，推荐标题附近显示“比较这2件”或“比较这3件”。每张产品卡同时提供“选择这件礼品”和“和其他商品比较”；比较仍位于同一顾问页面，不打开独立分析页。比较结果回答“这几件礼物怎么选”，默认围绕适合谁、适用场景、风格、文化表达、预算、定制和实用考虑展开，不展示新的总分、星级、雷达图或技术权重。

比较后聊天输入继续可用。系统应把“第一个和第三个哪个更适合教授”路由为当前推荐范围内的比较，把“那我选第一个”路由为现有选品动作，把“再现代一点”路由为需求调整并重新进入现有推荐流程。用户不需要重新描述已知需求，也不会因为比较而丢失当前推荐上下文。

比较结论使用当前需求和结构化商品事实。它可以说明“就目前信息会先考虑哪一件”以及不同侧重点下的取舍，但不能声称某件商品普遍更好。缺少可靠依据的价格、运输、交付、批量、便携或定制信息一律显示“待确认”或“暂无可靠信息”，不得把未知显示成“不支持”。

选择产品后，同页显示已选产品、需求摘要和“生成我的礼品方案”。最终方案包含定制方向、中英文文化介绍、Logo/题字/包装方向、预算和数量摘要、下一步及下载按钮。用户可以更换产品、调整需求和重新匹配。

比较结果下方提供“选择推荐款”“继续比较”“调整需求”。选择后保留当前 session 中的比较上下文；比较历史只用于当前 session，不因现有匿名分析授权而自动写入持久化存储。

## 5. 客户主界面禁用表达

主流程不显示 MVP、Wave 2、比赛原型、演示解析模式、parser mode、API Key、DeepSeek 状态、缺失/不确定字段、覆盖度、置信度、内部推荐模式、JSON 字段名或技术堆栈。赛事文档和数据合规字段继续保留。

页面底部“数据与服务说明”只说明目录依据、事实边界、最终服务确认和匿名分析用途。

## 6. 响应式与可访问性

- 主内容最大宽度 980px，以单栏为主；
- 760px 以下减少页面边距并禁止横向溢出；
- 产品图统一 4:3；
- 快捷按钮和主按钮使用一致圆角；
- 桌面端比较使用有行标题和列标题的结构化列式矩阵；
- 860px 以下自动切换为逐商品卡片，不能依赖横向滚动查看完整比较；
- “待确认”必须有可读文字，不能只依赖颜色、对勾或叉号表达证据状态；
- 核心功能不依赖自定义 JavaScript。

## 7. AI Shopping 动作与客户表达

客户界面只呈现顾问语言，不展示动作枚举。应用层在已有推荐后识别以下连续操作：

| 客户表达 | 应用动作 | 体验结果 |
|---|---|---|
| “帮我比较这三个” | `compare_recommendations` | 比较当前全部正式推荐 |
| “只比较前两个” | `compare_selected_products` | 按原推荐顺序缩小比较范围 |
| “第一个为什么更适合商务场景” | `explain_difference` | 只解释当前结果，不重新推荐 |
| “再现代一点” | `refine_recommendations` | 更新明确软偏好，重新执行既有推荐链 |
| “那我选第一个” | `select_product` | 继续既有内容与最终方案路径 |

Shopping 路由只在存在当前推荐时处理序号、比较、解释、调整和选择意图；没有当前推荐时，输入仍进入正常需求理解。路由不得读取或推断商品事实，也不得建立第二套会话状态机。
