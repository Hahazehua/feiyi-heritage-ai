# HAHA｜飞颐礼遇对话式礼品发现体验

## 1. 体验定位

客户打开应用后进入 AI Gift Discovery，而不是表单、后台或传统商城。页面以自然语言输入为核心，通过场景图片、简短对话、需求摘要和渐进式商品推荐，帮助客户从“还不知道送什么”走到“已经选好礼物”。

主路径保持为：

```text
表达场景 → 一次一个自然追问 → 当前礼赠方向 → 0–3 件正式推荐
→ 继续聊天或选择 → 生成专属礼赠方案 → 下载方案
```

所有阶段在同一页面展开，继续使用现有 `st.session_state`、`AgentTurnResult` 和统一 `run_agent_turn(...)` 入口。

## 2. Landing State

首屏使用暖白背景、墨色文字和深铜强调，品牌语为“选一份真正有意义的礼物”。大输入框紧随 Hero，客户不需要先理解产品分类。

下方展示固定的四个任务场景：海外商务礼赠、教授与长辈、企业周年、中国文化礼物。卡片采用一张横向主场景加三张图片覆盖小卡；图片、渐变和左下角文字共同构成单层可点击卡片。点击后立即形成用户消息并通过统一 Agent 入口开始对话。

参考图中借鉴的是输入优先、图片先于复杂字段、一个大场景加多个小场景、低密度留白和推荐内容自然下沉。没有复制其黑色主题、品牌、Logo、专有图标、商品文案或控件。

## 3. Conversation State

Landing 输入框位于 Hero 后的普通内容容器中，不固定到页面底部。第一条消息提交后，Landing Hero 和灵感卡消失并收缩为品牌栏；此时才启用底部 sticky composer。底部容器透明且不拦截后方交互，页面末尾保留安全间距，避免商品按钮在滚动到底时被遮挡。

用户与 HAHA 消息保留在同一内容流；HAHA 每轮最多追问一个问题，并按问题类型显示预算、风格、数量或对象的快捷回答。快捷回答和自由输入使用同一 Agent 入口。

当前礼赠方向使用客户语言的 Pills 呈现，未知项不展示内部字段名。客户可以调整需求、立即查看推荐、继续聊天或重新开始。推荐出现后聊天输入仍然保留，新消息会更新累计需求并重新匹配。

## 4. Recommendation / Selected / No Match

推荐最多 3 件，桌面端三列、移动端单列。卡片一级信息只有图片、中文名、目录价格、单句推荐理由和有真实数据支持的标签；八维评分、文化寓意、资料规格和定制能力收在“看看为什么适合”中。

选择后，卡片显示“✓ 已选择”，并出现生成方案、继续调整和换一件。选中状态不只依赖颜色。

0 结果时显示“目前还没有作品同时满足这些条件”，列出主要限制，并提供放宽预算、调整交期和查看接近方案。任何调整仍经过 Agent；30 件 reference-only 馆藏不会进入推荐。

## 5. Final Plan

最终方案是可阅读的礼赠方案卡，而不是 JSON 或表格。它包含产品图片、对象、场景、预算、定制方向、中文/英文文化表达和下一步。下载内容继续使用现有方案数据；客户也可以从方案状态继续调整。

## 6. Review Mode 与客户语言

客户页面不显示内部状态、解析器、模型错误、置信度、缺失字段、Skill 或 execution trace。LLM 不可用时保持正常客户体验。

Review Mode 继续由环境开关和 `?review_mode=1` 双门控；开启后在客户体验下方显示原有脱敏 Skill 状态、fallback、安全检查、耗时和输入/输出摘要。

## 7. 响应式与可访问性

- 内容最大宽度 1080px；
- 760px 以下卡片单列、输入框占满、按钮点击高度至少 48px；
- 页面禁止横向溢出，Pills 自动换行；
- 图片使用统一比例、可读 alt/caption，选中状态含文字；
- 核心流程使用 Streamlit 原生输入和按钮，可键盘操作，不依赖自定义 JavaScript。
